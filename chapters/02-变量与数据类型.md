# 变量与数据类型

> 一句话心智模型：**Go 的变量一出生就有确定零值（读不到垃圾）；rune 是"字"的编号、string 是"字"的编码（转换是解码不是补零）；slice 是一扇看数组的窗口，窗口共享是万恶之源。**

> 已沉淀：Part1 变量/常量/iota、Part2 string、Part3 struct 与方法、Part4 slice、Part5 map。Part6 控制流、Part7 函数待学后补充。

## 一、变量 / 常量 / iota

### 三种声明

```go
var x int        // ① 只声明 → 拿到"零值"
var x int = 42   // ② 声明 + 显式类型 + 初值
x := 42          // ③ 短声明：类型由右侧推导（只能在函数内用）
```

**心智模型：变量一出生就带"户口本"**——每个变量从出生就有确定的默认值，永远不会像 C 那样读到未初始化的内存垃圾。

### 零值表（`%#v` 打印验证）

| 类型 | 零值 |
|------|------|
| int / float | `0` |
| string | `""` |
| bool | `false` |
| 指针 / 切片 / map / chan / func / interface | `nil` |

注意：**nil 切片/map 并不是坏的**——`len(nil)=0`、`append(nil, x)` 直接可用（map 的 nil 只能读不能写，见 Part5）。

### 类型后置哲学

`var x int`（名字在前、类型在后）读起来是英语句子 "x is an int"。好处在复杂类型上体现得淋漓尽致：

```go
var f func(int) bool   // 从左往右读：f 是"接收 int、返回 bool"的函数
// C 写法 bool (*f)(int);  从里往外猜，痛苦
```

### 常量与 iota

```go
const Pi = 3.14     // 编译期确定；无类型常量，用到哪推成哪
const (
    A = iota        // 0
    B               // 1    iota = 块内行号，每行 +1
    C               // 2
)
```

**心智模型：iota 是 const 块内的"行号计数器"**，从 0 起每行自动 +1。用它做位标志最妙：

```go
const (
    FlagA = 1 << iota   // 1      0001
    FlagB               // 2      0010
    FlagC               // 4      0100
    FlagD               // 8      1000
)
```

`1 << n = 2ⁿ`，每个标志占一个独立二进制位。判断某位是否开启：`x & FlagB != 0`。`_` 可跳过编号：`A=iota, _, B` → B=2。

### 手写验证

**1. 零值**：声明 `var i int`、`var s string`、`var sl []int`、`var m map[string]int`，用 `%#v` 打印，看零值长什么样

```go
var i int
var s string
var sl []int
var m map[string]int
fmt.Printf("int=%#v string=%#v sl=%#v m=%#v\n", i, s, sl, m)
// int=0 string="" sl=[]int(nil) m=map[string]int(nil)
```

**2. iota 与下划线**：验证 `_` 能跳过编号（先猜 B 是多少再打印确认）

```go
const (
	A = iota // 0
	_        // 跳过 1
	B        // 2
	C        // 3
)
fmt.Println(A, B, C)   // 0 2 3
```

**3. iota 位移**：用 `1 << iota` 定义位标志，打印并解释为什么能当"位标志"

```go
const (
	FlagA = 1 << iota // 1      0001
	FlagB             // 2      0010
	FlagC             // 4      0100
	FlagD             // 8      1000
)
fmt.Println(FlagA, FlagB, FlagC, FlagD)   // 1 2 4 8
// 每个标志占一个独立二进制位，用 | 或起来互不干扰，x&FlagB!=0 判断是否开启
```

## 二、string：按字节想，别按字符想

### 心智模型

**string 是一串字节的只读视图。永远别按"字符"想，要按"字节"想。** 底层是一个头 `{ptr, len}` 指向一段只读字节数组，编码是 UTF-8（英文 1 字节、中文 3 字节）。

### 三个必踩的坑

**坑 1：`len(s)` 是字节数，不是字符数**
```go
len("你好")   // 6，不是 2！
```

**坑 2：两种遍历天差地别**
```go
for i := 0; i < len(s); i++ { }   // 按【字节】走
for i, r := range s { }           // 按【rune（码点）】走，i 会跳
```

**坑 3：切片 `s[i:j]` 切的是字节位**
```go
"你好"[:2]   // 切出半个"你"，乱码
"你好"[:3]   // 正好一个"你" ✅
```

### 为什么 range 的 i 会跳着走：UTF-8 自同步

**每个字符的领头字节自带"长度信息"**，解码器看一眼就知道要读几个字节，不用猜：

| 领头字节高位 | 字符宽度 |
|-------------|---------|
| `0xxxxxxx` | 1 字节（ASCII） |
| `110xxxxx` | 2 字节 |
| `1110xxxx` | 3 字节（中文在这档） |
| `11110xxx` | 4 字节（emoji） |
| `10xxxxxx` | 续接字节（不是开头） |

"中" = 3 字节 `E4 B8 AD`。`E4` = `1110 0100`，开头 `1110` → 查表 3 字节 → 后面再跟 2 个续接字节。解码器流程（`runtime/utf8.go` 的 `decoderune`）：

```go
case t3 <= s[0] && s[0] < t4:      // s[0]=E4，落在 3 字节区间
    r = rune(s[0]&0x0F)<<12 | rune(s[1]&0x3F)<<6 | rune(s[2]&0x3F)  // 抠出码点
    pos += 3                        // 索引跳 3 → range 的 i 就跳 3
```

手摇验证（自己写一遍就通了）：

```go
func runeWidth(b byte) int {
    switch {
    case b < 0x80: return 1   // 0开头
    case b < 0xE0: return 2   // 110
    case b < 0xF0: return 3   // 1110
    default:       return 4   // 11110
    }
}
for i := 0; i < len(s); {
    w := runeWidth(s[i])
    // 处理 s[i:i+w] 这一个完整字符
    i += w
}
```

### rune 是编号，string 是编码

**同一个"中"字，两个容器存的东西完全不同：**

| 容器 | 存的是 | 例子 |
|------|--------|------|
| string | 编码后的字节 | `e4 b8 ad`（3 字节） |
| rune | 身份证号（码点） | `20013` = `0x4e2d`（int32，4 字节） |

`[]rune` / string 互转是**解码/编码**（翻译编号↔字节），**不是补零**。rune 的 4 字节内存里是 `2d 4e 00 00`（数字 20013 的小端），不是 `e4 b8 ad` 补零。

`%q` 的引号也反映类型：rune/int 打单引号 `'A'`，string/[]byte 打双引号 `"A"`。

### 编号空间：能装的不等于合法的

| 量 | 数值 |
|----|------|
| rune(int32) 存储容量 | 2^32 ≈ 42 亿 |
| Unicode 合法编号空间 | `0x10FFFF+1` = 1,114,112（`runtime/utf8.go` 的 `maxRune`） |
| 实际已分配字符 | 约 14.9 万 |

超过 `0x10FFFF` 的 rune 不是合法字符，转字符串只会得到 `�`（U+FFFD 替换符）。**切片切到半个字符 → 残缺字节解码失败 → 也是 `�`。**

### 手写验证

**1. 长度陷阱**：`s := "hello"` 和 `t := "你好世界"`，先猜 `len` 各是多少，再打印确认

```go
s := "hello"
t := "你好世界"
fmt.Println(len(s), len(t))   // 5 12（中文每字 3 字节）
```

**2. 按字节 vs 按 rune 遍历**：对 `"A中B"` 分别用两种循环打印 `i` 和值，观察 `i` 的跨度

```go
str := "A中B"
// 按字节：i 每次 +1，中文碎成 3 个字节
for i := 0; i < len(str); i++ {
	fmt.Printf("[%d]=%c:%x ", i, str[i], str[i])
}
// [0]=A:41 [1]=ä:e4 [2]=¸:b8 [3]=­:ad [4]=B:42

// 按 rune：i 是字节坐标，跨过中文时跳 3
for i, r := range str {
	fmt.Printf("[%d]=%q ", i, r)
}
// [0]='A' [1]='中' [4]='B'   ← i 从 1 跳到 4
```

**3. 不可变性**：`a := "Go"; b := a + "lang"`，打印 a 和 b——a 变了吗？

```go
a := "Go"
b := a + "lang"
fmt.Println(a, b)   // Go Golang  ← a 没变，拼接产生新串
```

**4. 切片切半个中文**：`"你好"[:2]` 打印出来长什么样？

```go
fmt.Printf("%q\n", "你好"[:2])   // 半个"你" → 解码失败 → 乱码 �
```

> 加分：手摇解码器复刻 range（`runeWidth` 按领头字节判宽度），输出和 range 一模一样 `[0]='A' [1]='中' [4]='B'`。

## 三、struct 与方法

### 心智模型

**struct 是装字段的盒子；方法是"盒子上的技能"。值接收者 = 技能打在复印件上；指针接收者 = 技能打在原件上。**

### 定义 + 两种初始化

```go
type User struct {
    Name string
    Age  int
}

u1 := User{"阿绿", 25}              // 按字段顺序（字段多了易错）
u2 := User{Name: "阿绿", Age: 25}   // 按名字（推荐）
u3 := User{Name: "阿绿"}            // 没写的字段拿零值 → Age=0
```

### 值接收者 vs 指针接收者（核心）

```go
func (u User) Greet() string { return "Hi, " + u.Name }  // 值接收者：副本
func (u *User) Birthday()    { u.Age++ }                  // 指针接收者：原件

u := User{Name: "阿绿", Age: 25}
u.Birthday()      // 变量上调指针方法，Go 自动取 &u
fmt.Println(u.Age) // 26 —— 真改了
```

**怎么选**：要改字段 → 指针接收者；只读 / 要当值用 → 值接收者。

### 构造函数习惯（Go 没有构造器）

```go
func NewUser(name string, age int) *User {
    if age < 0 { age = 0 }
    return &User{Name: name, Age: age}
}
```

返回 `*User` 是惯例，因为后面往往要调指针方法。

### 不可寻址陷阱

```go
u.Birthday()              // ✅ u 是变量，可寻址，自动 &u
User{Name: "x"}.Birthday() // ❌ cannot call pointer method Birthday on User
```

**临时复合字面量不可寻址，没有地址可取**，指针方法调不了。

### 值复制 vs 指针复制（分水岭）

```go
u := User{...}     // u 是【值】
v := u; v.Age = 99 // v 是整体拷贝，改 v 不影响 u → u.Age 不变

p := NewUser(...)  // p 是【指针】
q := p; q.Age = 99 // q 只复制门牌号，p 和 q 指向同一间房 → p.Age 也变 99
```

### 手写验证

**1. 值 vs 指针接收者**：定义 `Counter`，值接收者 `Add()` 改内部字段，指针接收者 `Inc()` 改内部字段，分别调用后打印，观察哪个改了

```go
type Counter struct{ Num int }

func (c Counter) Add(x int) { c.Num += x }    // 值接收者
func (c *Counter) Inc(x int) { c.Num += x }   // 指针接收者

c := Counter{Num: 100}
c.Add(100)
fmt.Println(c.Num)   // 100  ← 值接收者改的是副本，没变
c.Inc(100)
fmt.Println(c.Num)   // 200  ← 指针接收者改的是原件，变了
```

**2. 不可寻址坑**：试试 `User{Name:"x"}.Birthday()` 能不能编译过

```go
// User{Name: "x", Age: 18}.Birthday()
// ❌ cannot call pointer method Birthday on User
// 临时复合字面量不可寻址，没有地址可取给指针方法
```

**3. 值语义复制**：`a := User{...}; b := a; b.Age = 99`，打印 a.Age 和 b.Age

```go
a := User{Name: "xxx", Age: 18}
b := a
b.Birthday()   // b 是 a 的整体拷贝，改 b 不影响 a
fmt.Printf("a.Age:%d, b.Age:%d\n", a.Age, b.Age)   // a.Age:18, b.Age:19
```

## 四、数组（slice 的地基）

> 本应是 slice 的前置知识，当初漏了，补遗于此。**读 slice 之前先读这一节。**

### 心智模型：数组 = 一块"长度焊死"的连续内存

```go
[5]int    // 一个类型：长度 5 写死在类型名里
[3]int    // 另一个类型：长度 3 —— 和 [5]int 是两种类型！
```

**Go 数组和 C 完全不同**：C 的数组是指针的语法糖（传参会 decay 成指针）；Go 的数组是**实打实的值**——长度是类型的一部分，赋值/传参都是整块拷贝，绝不自动 decay 成指针。

### 声明三式

```go
var a [3]int            // 全零 [0 0 0]
b := [3]int{1, 2, 3}    // 定长字面量
c := [...]int{1, 2, 3}  // 长度推断 → [3]int（编译器数元素，编译还原）
```

### 三个核心特性

**① 值是整块拷贝（不是共享）**

```go
a := [3]int{1, 2, 3}
b := a          // 整个数组复制一份！
b[0] = 99
fmt.Println(a)  // [1 2 3] ← a 没变
```

slice 呢？`sl2 := sl` 只复制 24 字节窗口头，底层共享。**`[N]T` 值拷贝，`[]T` 窗口共享**——这是 slice 内部结构的前提。

**② 长度是类型一部分，不能混用**

```go
a := [3]int{1,2,3}
a = [4]int{1,2,3,4}  // ✗ 编译错误：cannot use [4]int as [3]int
```

**③ 不 decay（不会退化成指针）**

C 里数组传函数自动变指针；Go 不这样，`[5]int` 就是 `[5]int`，要转 slice 必须显式 `arr[:]`。

### 数组 vs slice（为什么日常用 slice）

| | `[3]int` 数组 | `[]int` slice |
|---|---|---|
| 长度 | 固定、写死在类型里 | 动态（len/cap 在窗口头里） |
| 传参 | **整块拷贝**（`[100]int` = 800 字节 memcpy） | 只拷 24 字节 header |
| append | 不能 | 能 |
| 跨长度互操作 | 不行（类型不同） | 随便 |
| 可比较 `==` / map key | ✅（元素可比时） | ❌（slice 不可比较） |

### 数组的用武之地（不多但真实）

1. **slice 的地基**：`arr[:]` 切出 slice（窗口指向数组）
2. **固定大小 + 可比较 → map key**：`digest := [16]byte{...}`（摘要）直接当 key，slice 做不到

### 手写验证

```go
var a [3]int
fmt.Printf("%v %T\n", a, a)         // [0 0 0] [3]int

arr := [3]int{1, 2, 3}
cp := arr
cp[0] = 99                          // 数组拷贝互不影响
fmt.Println(arr, cp)                // [1 2 3] [99 2 3]

sl := []int{1, 2, 3}
sl2 := sl
sl2[0] = 99                         // slice 共享底层
fmt.Println(sl, sl2)                // [99 2 3] [99 2 3]

// 数组可当 map key
seen := map[[2]int]bool{}
seen[[2]int{3, 4}] = true
fmt.Println(seen)                   // map[[3 4]:true]
```

## 五、slice

### 心智模型

**slice 是一扇看数组的"窗口"，窗户上贴着三张标签：`ptr`（看哪块内存）、`len`（能看多长）、`cap`（能看到多远）。**

### 内心结构（三字段）

```go
type slice struct {
    ptr unsafe.Pointer  // 指向底层数组某个位置
    len int             // 当前有效长度
    cap int             // 最多能用到哪
}
```

### 声明

```go
var s []int          // nil 切片（ptr=nil, len=0, cap=0）—— 但 append 能直接用
s := []int{1, 2, 3}  // 字面量（cap = 长度 = 3）
s := make([]int, 5)      // 长度 5，全是零值
s := make([]int, 0, 10)  // 预留容量 10（关键：避免反复扩容拷贝）
```

### 窗口共享（重点坑）

```go
a := []int{0, 1, 2, 3, 4, 5}
b := a[1:4]       // b=[1 2 3]，len=3 cap=5
b[0] = 99
fmt.Println(a)    // [0 99 2 3 4 5] ← a 也被改了！
```

**`a[1:4]` 不是复制，是在同一块数组上换窗口位置。** 改窗口里的东西，数组上的东西跟着变。

### append 与扩容：什么时候断开共享

```go
c := []int{1, 2, 3}
d := c
d = append(d, 4)  // c 的 cap=3 满了 → d 换更大的数组（共享断开）
d[0] = 99
fmt.Println(c)    // [1 2 3] ← c 还指着老数组，没变
```

**append 先问"窗口能往后拉吗（len < cap）？"** 能 → 原地扩（此时仍共享）；不能 → 搬家换数组（共享断开）。

### 扩容规则（`runtime/slice.go` 的 `nextslicecap`）

```go
if newLen > doublecap { return newLen }          // ① 一次塞太多，直接按需要长度
if oldCap < threshold { return doublecap }       // ② 小切片(旧cap<256)：翻倍
newcap += (newcap + 3*threshold) >> 2            // ③ 大切片：约 1.25 倍逐轮逼近
// 最后还要按内存 size class 向上取整（所以会出现 848 这种非 2 的幂）
```

实测成长曲线：`1→2→4→8→16→32→64→128→256→512→848→…`（<256 翻倍，>256 放缓）。

**工程教训**：大概知道容量就 `make([]int, 0, 容量)` 预留，避免反复扩容 + 整体 memmove 拷贝。

### 手写验证

**1. 窗口共享**：`a := []int{1,2,3,4,5}; b := a[1:4]`，改 `b[0]` 和 `b[2]`，打印 `a`——猜哪些位置被改了

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:4]   // b 是 a 的窗口：b[0]→a[1], b[1]→a[2], b[2]→a[3]
b[0] = 99
b[2] = 100
fmt.Println(a)   // [1 99 3 100 5]  ← a 的序号 1 和 3 被改了
```

**2. len/cap 观察**：`s := make([]int, 2, 5)` 连续 `append` 5 次，每次打印 `len/cap`，找扩容规律

```go
s := make([]int, 2, 5)   // len=2 cap=5
for i := 0; i < 5; i++ {
	s = append(s, 8)
	fmt.Printf("len:%d, cap:%d\n", len(s), cap(s))
}
// append 第 4 个元素时触发扩容 → cap 跳到 10（旧 cap=5<256，翻倍）
```

**3. append 前后共享对比**：`x := []int{1,2,3}` vs `x2 := make([]int,3,6)`，谁扩容谁共享

```go
x := []int{1, 2, 3}     // cap=3
y := append(x, 4)       // 扩容 → len=4 cap=6，与 x 断开共享
y[0] = 100
fmt.Println(x[0])       // 1  ← x 没变（搬新家了）

x2 := make([]int, 3, 6) // cap=6 预留
y2 := append(x2, 4)     // 不扩容 → 共享底层
y2[0] = 11
fmt.Println(x2[0])      // 11 ← x2 也变了（还在同一块数组）
```

## 六、map

### 心智模型

**map 是一本"哈希账本"：key 做哈希定位到桶，值记在桶里。读不存在的键 → 拿到零值（账上没这行 = 零）。账本传给谁，谁记一笔你都能看见（引用语义）。**

### 声明与读写

```go
var m map[string]int        // nil map：能读，不能写！
m := make(map[string]int)   // 空 map，能写
m := map[string]int{"a": 1} // 字面量

m["b"] = 2                  // 记账
v := m["不存在的键"]         // 0（零值！不报错）
v, ok := m["a"]             // ok 判断是否存在（读不存在只拿零值，无法区分"没有"和"值为0"）
delete(m, "a")              // 销账
```

**零值陷阱**：`m["不存在"]` 返回 `0` 而不是报错。判断存在必须用 `, ok` 双返回值。

### nil map vs 空 map（空信封 vs 空抽屉）

| 写法 | 状态 | 读 | 写 |
|------|------|----|----|
| `var m map[string]int` | nil（零值） | 返回零值 ✅ | **panic** 💥 |
| `m := map[string]int{}` | 空（非 nil） | 返回零值 ✅ | 正常 ✅ |

- `var m` = **空信封**（没有底层哈希表）；`m := map[string]int{}` = **空抽屉**（哈希表真实存在）
- 两者 `len` 都是 0、都能读；**唯一区别在写**——nil 写会 `panic: assignment to entry in nil map`

**为什么 slice 没这个坑**：`append(nil, x)` 能自动分配，因为 append 是函数、**返回新 slice**（`s = append(s, x)`）；而 `m[k]=v` 是**原地修改、不返回**，Go 无法"分配个新的交还给你"，所以选择立刻 panic——写未初始化的 map 99% 是编程错误，宁可响亮失败。

### 类型名 vs 复合字面量（图纸 vs 实物）

```go
map[string]int       // 类型名（图纸）：只能出现在【类型位】
map[string]int{}     // 复合字面量（实物）：出现在【表达式位】

m3 := map[string]int    // ❌ map[string]int (type) is not an expression
m3 := map[string]int{}  // ✅ 构造一个空 map
```

- **类型位**：函数参数、返回值、`var x T`、struct 字段——要"类型名"
- **表达式位**：`:=` 右边、函数实参、`return` 的值——要"值"；裸类型名给不出值
- 其他类型同理：`[]int`（图纸）vs `[]int{}`（实物）、`struct{}` vs `struct{}{}`

### 遍历无序

```go
for k, v := range m {   // 顺序随机，每次可能不同
}
```

Go 故意打乱遍历起点，逼你不依赖顺序。**string 的 key 可以是任意字节**（含控制字符）——用 `string(byte(i))` 当 key 打印会全是乱码（`\x00`~`\x13` 不可见），排查字符串内容用 `%q`。

### 引用语义

```go
func addOne(m map[string]int) { m["x"] = 100 }   // 改的是同一个账本
m := map[string]int{}
addOne(m)
fmt.Println(m["x"])   // 100 —— 函数外也看到了
```

### 三个坑

1. **nil map 写 panic**（见上）
2. **key 必须可比较**：slice / map / func 不能当 key（编译错），`chan` 可以（可比较）
3. **并发读写直接 panic**：`fatal error: concurrent map read and map write`（并发章节再拆）

### 手写验证

**1. 零值陷阱**：`m := map[string]int{}`，读三个不存在的键，看返回什么；再用 `, ok` 确认它们都不存在

```go
m1 := map[string]int{}
val1 := m1["A"]
val2 := m1["B"]
val3 := m1["C"]
fmt.Printf("val1:%v, val2:%v, val3:%v\n", val1, val2, val3)   // 0 0 0

val4, ok := m1["A"]
fmt.Printf("ok=%v, val4=%v\n", ok, val4)   // ok=false, val4=0
```

**2. 无序遍历**：往 map 里塞 20 个键值，遍历打印两次，对比顺序（多跑几次）

```go
m2 := map[string]int{}
for i := 0; i < 20; i++ {
	m2[fmt.Sprintf("%d", i)] = i
}
for k, v := range m2 { fmt.Println(k, v) }
// 每次运行顺序都不同（Go 故意打乱遍历起点）
```

**3. 引用语义**：写个函数往 map 里加键，函数外打印确认"透出去了"

```go
func Add(m map[string]int) { m["hello"] = 1 }   // 改的是同一个账本
m3 := map[string]int{}
Add(m3)
fmt.Println(m3["hello"])   // 1  ← 函数外也看到了
```

**4. nil map 陷阱**：`var m map[string]int`，先读（不报错？），再写（panic？）

```go
var m4 map[string]int
fmt.Println(m4["x"])   // 0  ← 读 nil map 不报错，返回零值
m4["a"] = 1            // 💥 panic: assignment to entry in nil map
```

## 七、用 map 实现 Set：为什么是 `map[string]struct{}`

### 心智模型

Go **没有内置 Set**。惯用法：**map 的 key 天然去重，直接拿 key 当集合元素**。value 放什么都不影响去重，但选 `bool` 还是 `struct{}`，决定了好不好用、会不会埋坑。

```go
seen := map[string]bool{}         // A: value 是 bool
seen := map[string]struct{}{}     // B: value 是空结构体（0 字节，惯用法）
```

### A 的隐蔽 bug：`if m[k]` 单值判断把"值真假"误当"存在性"

map 里完全可能出现**"key 存在但值是 false"**的 entry（map 同时记"处理结果"、被共享、数据合并/恢复时）。这时用单值判断会漏判：

```go
done := map[string]bool{}
done["job-ok"] = true
done["job-fail"] = false   // job-fail 处理过了（key 存在），只是失败了

if !done["job-fail"] {     // 单值判断 → 以为它"没处理过"
    // ❌ 去重失效，重复处理 job-fail
}

// 正确救法：_, ok 判存在，别用单值
if _, ok := done["job-fail"]; ok { }
```

### B 的精妙：`struct{}` 没有"真假"可言 → **编译期就禁止你写单值判断**

```go
seen := map[string]struct{}{}
seen["go"] = struct{}{}

// if seen["go"] { }   // ✗ 编译错误：non-boolean condition（struct{}{} 当不了条件）
// → 想偷懒写 if m[k] 都不行，逼你写 _, ok，从根上杜绝上面的漏判
```

### 附带好处：0 字节

`struct{}` 是 Go 里唯一占 **0 字节**的类型。作为 map value 只表达"存在"，不存别的；bool 占 1 字节还留着"真假"语义噪声。

### 手写验证（先猜输出）

```go
done := map[string]bool{}
done["job-ok"] = true
done["job-fail"] = false // job-fail 处理过（key 在），只是失败

for _, id := range []string{"job-ok", "job-fail", "job-new"} {
    if !done[id] {   // 单值判断
        fmt.Println("视为未处理:", id)
    }
}
// 输出：
//   视为未处理: job-fail   ← ❌ bug：它明明处理过，被当"未处理"
//   视为未处理: job-new    ← ✅ 真没处理过

// 换 struct 版：单值判断直接编译不过，只能 _, ok
seen := map[string]struct{}{}
seen["job-ok"] = struct{}{}
seen["job-fail"] = struct{}{}
for _, id := range []string{"job-ok", "job-fail", "job-new"} {
    if _, ok := seen[id]; !ok {
        fmt.Println("视为未处理:", id)
    }
}
// 输出：
//   视为未处理: job-new    ← ✅ 只有真没处理的
```

## 小结

- **变量**：三种声明；零值保证"出生即确定"；iota 是块内行号，配合 `1<<iota` 做位标志
- **string**：按字节想；`len`=字节数；range 按 rune 走且 i 跳着走（UTF-8 领头字节自报宽度）；rune 是编号、string 是编码
- **struct**：值接收者打复印件、指针接收者打原件；临时值不可寻址；值复制互不影响、指针复制共享
- **slice**：ptr/len/cap 三标签；切片换窗口共享底层；append 塞满就搬家断开共享；扩容 <256 翻倍、>256 放缓
- **map**：哈希账本；nil（信封）只读、空（抽屉）可写；读不存在拿零值要靠 `,ok`；遍历无序；引用语义
