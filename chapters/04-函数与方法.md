# 04-函数与方法

> 一句话心智模型：**函数是"加工厂"——参数进料、返回值出料。Go 用多返回值把错误显式化，用"一切传值"简化传参规则，用 defer 把收尾动作就近写好。**

> 注：**方法（接收者函数）已在第二章三节「struct 与方法」讲过**（值接收者 vs 指针接收者）。本章聚焦**函数**本体：多返回值、传值语义、闭包、defer。

---

## 一、多返回值 + 命名返回值

### 心智模型

C/C++ 要么用指针出参、要么用全局状态、要么引入异常——Go 干脆让一个函数**同时交出"结果 + 错误"**。这是 Go 错误处理的地基：`(值, error)` 模式。

### 语法

```go
// 语法：func 名(参数) 返回值 { 体 }

// 多返回值（最常用）：
func div(a, b int) (int, error) {
    if b == 0 {
        return 0, fmt.Errorf("divide by zero")
    }
    return a / b, nil
}

// 命名返回值：名字 = 函数体内的变量，可裸 return
func min(x, y int) (m int) {
    if x < y { m = x } else { m = y }
    return          // 等价 return m，把 m 当前值交出去
}
```

### 手写验证

```go
q, err := div(10, 3)       // q=3, err=nil
if err != nil { /* 处理 */ }
```

## 二、一切传值（Go 没有引用传参）

### 心智模型

C++ 可以 `func(&n)` 引用传参。Go 不行——**参数一律传值（拷贝）**。但这不等于"函数内改不了外面的数据"：slice/map 传的拷贝，恰好是它们的心脏（数组指针 / hmap 指针）。

### 三条规则

```go
// ① int/string/struct：传副本，函数内改了外部无感
func add1(n int) { n++ }          // 外部 n 不变

// ② slice：传"三字段头部(ptr/len/cap)"的副本
func tweak(s []int) {
    s[0] = 99          // 扩容前：写同一块数组 → 外部能看到
    s = append(s, 100) // cap 满(2/2) → 扩容搬家，s 指向新数组
    s[1] = 98          // 扩容后：写的是新数组 → 外部看不见！
}

// ③ map：传 hmap 指针的副本 → 函数内改内容，外部能看到
func set(m map[string]int) { m["a"] = 1 }  // 外部 m 里有 "a":1
```

呼应 slice/map 章节的内部结构：**"一切传值"是表，里子是"拷贝的心脏"**。所以 slice 元素能改、slice 长度改不了；map 内容能改。

**扩容 = "断开共享"的分水岭**（把 ch02 slice 扩容和"一切传值"焊在一起的规则）：

- 扩容**前**：本地 s 与外部共享同一底层数组，写元素外部**看得见**（`s[0]=99` 生效）
- **一旦 append 触发扩容**：本地 s 搬家到新数组，**之后对元素的一切写入都落在外部看不见的新数组上**（`s[1]=98` 不生效）——不只是 len 改不了，**连元素写入也断了**
- 若 cap **足够**（如 `make([]int, 2, 4)`）：append 原地扩不搬家，扩容后的元素写入外部**仍然看得见**，只是外部 len 仍是 2

### 手写验证

```go
s := []int{1, 2}
tweak(s)
fmt.Println(s[0], len(s))   // 99 2（扩容前写入的元素改到了，长度没变）

m := map[string]int{}
set(m)
fmt.Println(m)              // map[a:1]
```

**扩容断连对比验证**：同一份 tweak，cap 不同，外部能看到的完全不同：

```go
// 场景 A：cap 不足 → append 扩容搬家 → 扩容后的写入全部失效
s1 := []int{1, 2}            // len=2 cap=2
tweak(s1)
//   tweak 内部变成 [99 98 100] cap=4（搬去新数组）
fmt.Println(s1)              // [99 2]  ← s1[1] 还是 2：98 写到了新数组

// 场景 B：cap 充足 → append 原地扩 → 写入仍然共享
s2 := make([]int, 2, 4)      // len=2 cap=4
tweak(s2)
fmt.Println(s2)              // [99 98] ← 窗口 len=2 只看到前两个
fmt.Println(s2[:3])          // [99 98 100] ← 100 写进了共享数组 index 2，
                             //   只是超出外部 len 的窗口。把窗口拉到 [:3] 就能看到
```

## 三、闭包：一等公民 + 捕获

### 心智模型

Go 里**函数是一等公民**：能赋给变量、当参数传、当返回值返回。**闭包 = 函数 + 它捕获的外层变量**。捕获是**按引用共享**——不是值的快照，闭包和外层共享同一个变量。

### 语法

```go
func counter() func() int {
    n := 0
    return func() int { n++; return n }  // n 被捕获，多次调用共享同一个 n
}
// c := counter(); c()→1, c()→2, c()→3
```

### 重点坑：循环变量捕获（Go 1.22 语义变更）

```go
var funcs []func()
for i := 0; i < 3; i++ {
    funcs = append(funcs, func() { fmt.Println(i) })
}
for _, f := range funcs { f() }
```

- **Go 1.22 之前**：循环变量 `i` 是**同一个变量**被反复改值，所有闭包捕获同一个 i → 执行时循环早结束，`i=3`，全打印 **`3 3 3`**。老解法是循环体内 `i := i` 再造副本。
- **Go 1.22 起**：每次迭代声明**全新变量**，每个闭包各自持有自己的 i → 打印 **`0 1 2`**，`i := i` 不再需要。
- **判定靠 `go.mod` 的 go 指令**：module 声明 `go 1.22` 走新语义；声明 `go 1.21` 即使工具链再新也走旧语义——版本 gating 由 go.mod 说了算。

### 手写验证

```go
var funcs []func()
for i := 0; i < 3; i++ {
    funcs = append(funcs, func() { fmt.Println(i) })
}
for _, f := range funcs { f() }
// 输出（go 1.22）：
//   0
//   1
//   2
```

## 四、defer：延迟收尾，但参数立即求值

### 心智模型

`defer X` 把 X **注册到函数返回前执行**。用处：把"收尾动作"写在开头，**就近配对着资源**，函数退出时自动跑。多条 defer **LIFO（后注册先执行）**。

### 三条规则

```go
// ① LIFO：后注册的先执行
func demo() {
    i := 1
    defer fmt.Println("defer1:", i)    // ③ 最后执行
    defer fmt.Println("defer2:", i+10) // ② 先执行（LIFO）
    fmt.Println("i已改成:", i)          // ① 函数体先跑
}
// 输出顺序：i已改成: 99 → defer2: 11 → defer1: 1

// ② 参数立即求值：defer 的实参在 defer 语句处就求值了（不是函数返回时）
//    上例 defer1 打印 1（i 那时是 1），不是 99

// ③ defer 能修改【命名返回值】
func f() (n int) {
    defer func() { n++ }()   // 在交出返回值前最后改一把 n
    return 5                 // 先 n=5，defer 再 n=6
}
// f() 返回 6
```

### ③ 的时序（信封比喻）

```
func f() (n int) {
    defer func() { n++ }()
    return 5
}

① return 5 求值 → 把 5 装进"命名返回值信封"      → n = 5
② defer 夹在"return 求值"和"真正返回"之间执行      → n = 6
③ 信封才交出去 → 调用者收到 6
```

- **命名返回值** = 函数开头摆好的**信封**，`return 5` 把 5 装进去，defer 在递出前还能打开信封改值 → 返回 6
- **无名返回值** = `func f() int { ...; return 5 }`，信封当场封死，defer 没有可改的变量 → 返回 5

### 常用场景：资源释放

```go
func readFile(name string) ([]byte, error) {
    f, err := os.Open(name)
    if err != nil { return nil, err }
    defer f.Close()   // 开头就近写关闭，函数任何 return 都会触发
    return os.ReadFile(name)  // 简化示意：实际用 io.ReadAll
}
```

### 手写验证

```go
func demo() {
    i := 1
    defer fmt.Println("defer1:", i)
    defer fmt.Println("defer2:", i+10)
    i = 99
    fmt.Println("i已改成:", i)
}
// i已改成: 99
// defer2: 11     ← LIFO：后注册先执行
// defer1: 1      ← 参数在 defer 语句处已求值（1），不是 99

func f() (n int) {
    defer func() { n++ }()
    return 5
}
// f() → 6：return 5 先赋给 n，defer 递出前把 n++ 到 6
```

## 小结

- **多返回值**：`(值, error)` 模式把错误显式化，不靠异常
- **一切传值**：int/string/struct 传副本；slice/map 传的是"心脏"（数组指针/hmap 指针）——元素能改、长度/引用改不了
- **闭包**：函数是一等公民，捕获外层变量按引用共享；**循环变量捕获在 Go 1.22 起每次迭代独立**（由 go.mod 指令决定）
- **defer**：延迟收尾 + LIFO + **参数立即求值**；夹在"return 求值"和"真正返回"之间，能改命名返回值
