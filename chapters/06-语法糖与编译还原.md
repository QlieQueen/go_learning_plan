# 06-语法糖与编译还原

> 一句话心智模型：**语法糖 = 编译器替我们写的样板代码。认得 `:=` 背后是 `var x = <expr>`，认得 `...int` 背后是 `[]int`——就读得懂编译器在做什么。**

第二章全貌（进度）：✅ `:=` + 变参 + make vs new + 指针可寻址性（本篇）｜⬜ for-range 还原、复合字面量专题、方法值、go/defer/select 还原

## 一、`:=` 短变量声明

### 心智模型

`x := 1` **⇔** `var x = 1`（类型由右侧推断）。它是"声明"的简写，**不是赋值**——所以才有"左侧至少一个新变量"的规则。

### 核心规则：左侧至少一个"新变量"

```go
x := 1
x := 2        // ✗ 编译错误：no new variables on left side of :=（没有任何新变量）

x := 1
x, y := 2, 3  // ✓ y 是新变量 → 合法（x 同作用域重声明）
```

**为什么要留这个口子？—— `err` 惯用法**：

```go
f1, err := os.Open("a.txt")   // f1 新、err 新
f2, err := os.Open("b.txt")   // f2 新、err 同作用域复用 → 合法
                              // 不用 var err error 每次重新声明
```

### 三条限制

- **包级作用域不能用 `:=`**：包级是"声明区"，只认 `var`；`:=` 是"语句"，只能在函数内
- 左侧不能带显式类型：`x int := 1` 是错的（类型交给推断）
- 默认类型由无类型常量决定：`i := 1`→`int`、`c := 'A'`→`int32`、`f := 1.5`→`float64`、`s := "hi"`→`string`

### 复用 vs 遮蔽（易混）

```go
// 同作用域 = 复用：err 还是那个变量，被重新绑定
fA, errA := demo("flat1")
fB, errA := demo("flat2")  // errA 复用 → 现在 = flat2

// 嵌套作用域 = 遮蔽：if 块里的 err2 是全新变量，恰好同名遮住外层
f2, err2 := demo("outer")
if f2 == 0 {
    f3, err2 := demo("inner")  // 新 err2（遮蔽）
    // 这里 err2 = inner
}
// 出了 if：err2 = outer ← 外层没被嵌套块改掉
```

**判断口诀：`:=` 允许重声明，但"复用"只发生在同一层大括号里；跨了一层大括号就是"遮蔽"（新变量）。**

### 手写验证

```go
x := 1
x, y := 2, 3    // ① 合法：y 新
// x := 4       // ② 唯一编译错误
x, y = 5, 6     // ③ 赋值(=)，合法
x, z := 7, 8    // ④ 合法：z 新
fmt.Println(x, y, z)   // 7 6 8

c := 'A'
fmt.Printf("%T", c)    // int32（rune 是 int32 的别名，%T 显示别名底层）
```

## 二、`...` 变参

### 心智模型

**变参是 slice 的语法糖——编译还原后函数体内就是一个 `[]T`。**

```go
func sum(nums ...int) int  // nums 在函数体里就是 []int
```

### 三种调用

```go
sum(1, 2, 3)          // 编译器悄悄组一个 []int{1,2,3}
sum()                 // 零个参数 → nums == nil（遍历天然安全）
s := []int{4, 5, 6}
sum(s...)             // 已有 slice 必须用 ... 展开
// sum(s)             // ✗ 编译错误：cannot use s (type []int) as type int
```

### append 的真相

```go
func append(slice []T, elems ...T) []T
```

append 自己就是变参——所以 `append(s, s2...)` 才成立：`s2` 作为 `elems` 展开。**变参与 slice 是同一枚硬币的两面**：声明时 `...T` 收编成 slice，调用时 `s...` 把 slice 拆回元素。

### 手写验证

```go
func sum(nums ...int) int {
    total := 0
    for _, v := range nums { total += v }
    return total
}

fmt.Println(sum())           // 0（nums==nil，for range 不 panic）
fmt.Println(sum(1, 2, 3))    // 6
s := []int{4, 5, 6}
fmt.Println(sum(s...))       // 15
```

## 三、make vs new（+ 复合字面量对照）

### 心智模型

值怎么"诞生"？三种姿势：

| 姿势 | 例子 | 得到 | 适用 |
|---|---|---|---|
| 复合字面量 | `[]int{1,2,3}`、`Person{"x",1}` | 直接摆好的值 | 任何类型 |
| `make` | `make([]int, 3)` | **初始化好的值**（非指针） | **只限 slice / map / chan** |
| `new` | `new(Person)` | **指向零值的指针** `*T` | 任何类型 |

**为什么 `make` 只限 slice/map/chan 这三个？** 因为它们的零值（nil）**不能直接用**：

| 类型 | 零值 | 直接用会怎样 |
|---|---|---|
| slice | `nil` | append 能用，但 `s[0]=` **panic**（越界） |
| map | `nil` | `m["a"]=` **panic**（nil map 赋值） |
| chan | `nil` | 收发**永久阻塞** |

`make` = 运行时搭内脏（`makeslice` / `makemap` / `makechan`，分配底层数组/桶/缓冲）；`new` = 只是"给一块清零内存的指针"，**干不了搭内脏的活**。

### 对照表

| 写法 | 返回 | 能直接写吗 |
|---|---|---|
| `make([]int, 3)` | `[]int`（len=3，底层数组已就位） | ✅ |
| `new([]int)` | `*[]int`（指向 nil slice） | ❌ `(*s)[0]=` panic |
| `make(map[string]int)` | `map`（空 map 就绪） | ✅ |
| `new(map[string]int)` | `*map`（指向 nil map） | ❌ 写 panic |
| `new(Person)` | `*Person`（零值） | ✅（但需逐步赋值） |
| `&Person{Name:"x"}` | `*Person`（带初值） | ✅ 一步到位 |

### `&T{}` 惯用法 vs `new`

- `new(T)` + 逐步赋值 = **两步语句**
- `&T{...}` = **一步表达式**，能直接 inline 进 `return` / 参数 / 结构体字段 → 更常用
- 语义近似：`new(T) ≈ &T{}`（对零值）；**要带初值必须用 `&T{...}`**

### 数组字面量 vs 切片字面量（题 4 实锤）

```go
[...]int{1,2,3}   // 数组：长度写死在类型里 → [3]int，赋值 = 深拷贝
[]int{1,2,3}      // 切片：窗口 → []int，赋值 = 复制 header，共享底层数组
```

数组和 slice 的赋值行为差在"值 vs 窗口"——这正好接上 ch02 的 slice 三字段。

### 手写验证

```go
s := make([]int, 3)        // []int 非指针
s[0] = 7                   // ✅ 能写
ns := new([]int)           // *[]int，*ns == nil
// (*ns)[0] = 1            // ✗ panic: index out of range

nm := new(map[string]int)  // *map，*nm == nil
// (*nm)["a"] = 1          // ✗ panic: assignment to entry in nil map
// make(Person)            // ✗ 编译错误：make 只接受 slice/map/chan

arr := [...]int{1,2,3}     // [3]int（值类型）
arr2 := arr
arr2[0] = 99               // arr[0] 还是 1（深拷贝）
sl := []int{1,2,3}
sl2 := sl
sl2[0] = 99                // sl[0] 变成 99（窗口共享底层！）
```

## 四、指针自动解引用与可寻址性

### 心智模型：指针 = 门牌号，可寻址 = 有没有固定房间

可寻址（addressable）的物理意思：**x 有一个稳定、安全、归它管的内存位置**。`&x` = "告诉我 x 住几号房"；`*p` = "按 p 记的房号敲门进屋"。

编译器在两种地方自动帮你省事：

- **自动解引用**：`p` 是 `*T`，写 `p.Name` 自动变 `(*p).Name`，`p.Say()`（值接收者）自动变 `(*p).Say()`
- **自动取地址**：值**可寻址**时，遇到需要指针的场合自动 `&v`（最常见：指针接收者方法调用）

### 可寻址性 = 三条物理原因的推论（不是背的）

| 表达式 | 可寻址? | 物理原因 |
|---|---|---|
| 变量 `v` | ✅ | 租的固定房间 |
| 指针解引用 `*p`、slice/数组元素 `s[i]` | ✅ | 位置确定 |
| 可寻址对象上的字段 `p.Name` | ✅ | 房间组合的一部分 |
| `&T{...}` | ✅ | 编译器造匿名变量再取址 |
| **map 元素 `m[k]`** | ❌ | **会搬家**：扩容 rehash 把元素搬到新桶，记下的房号作废 |
| **函数返回值 `mk()`** | ❌ | **现炒现卖**：临时值，没有固定落点 |
| **字符串字节 `s[i]`** | ❌ | **共享只读**：可能被子串共享的公告板，不许涂改 |

**一句话：会搬家的（map 元素）、现炒的（函数返回值）、共享只读的（字符串字节）——都不给地址。**

### map 元素的实战铁律

指针接收者方法 = 原地改原对象 → 要地址 → map 元素给不了 → 编译错；值接收者方法 = 复制一份算 → 不需要地址 → 编译过：

```go
type Counter struct{ n int }
func (c *Counter) Inc()    { c.n++ }      // 指针接收者：要原地改
func (c Counter) Val() int { return c.n } // 值接收者：只读复制

m := map[string]Counter{}
m["a"].Val()   // ✅ 值接收者：读值复制，不需要地址
m["a"].Inc()   // ✗ cannot call pointer method Inc on Counter（元素会搬家，拿不到地址）
```

解法两种：
1. **取出来 → 改 → 放回去**：`c := m["a"]; c.Inc(); m["a"] = c`
2. **map 存指针**：`m := map[string]*Counter{}`，`m["k"] = &Counter{}`，之后 `m["k"].Inc()` 直接 OK —— 桶怎么搬都行，指针指向的 Counter 是独立分配的，家不在桶里（`m["k"]` 本身就是 `*Counter`，连 `&` 都不用）

### string vs slice：为什么一个只读一个可写（C++ 视角）

把 Go string 想成 C++ 的 **`std::string_view`**（不拥有、只读、切片零拷贝的共享视图），**不是** `std::string`（拥有可写 buffer、拷贝子串的容器）：

| | `"hello"` string 字面量 | `[]byte("hello")` slice 字面量 |
|---|---|---|
| 字节住哪 | 共享只读区（字面量在二进制 rodata；运行期拼接的在堆上，**但都只读**） | 运行期新分配的可写数组（私产） |
| 子串 | 自动共享、不拷贝 | 只有你显式切片才共享 |
| 能原地改吗 | 永远不能（类型层面保证） | 能，你的私产 |

**为什么 Go 让字符串可共享**：切片零拷贝、传参零拷贝。**但零拷贝只有在"字节永远没人改"时安全** → 所以 string 字节不可变 → 不许拿地址。

### 手写验证

```go
// Rule1 自动解引用
p := &Person{Name: "alice"}
p.Name = "bob"            // (*p).Name
p.Say()                   // 值接收者 → (*p).Say()

// Rule2 自动取地址（变量可寻址）
v := Person{Name: "carol"}
v.SetName("dave")         // (&v).SetName

// Rule3 slice 元素可寻址 → 指针接收者 OK
s := []Person{{Name: "eve"}}
s[0].SetName("frank")     // &s[0]

// 不可寻址三行（go build 实测报错）：
// _ = &mk()        // cannot take address of mk() (value of type Person)
// m["a"].Inc()     // cannot call pointer method Inc on Counter
// _ = &str[0]      // cannot take address of str[0] (value of type byte)
```

## 小结

- **`:=` 的真相**：`var x = <expr>` 的简写，不是赋值；左侧**至少一个新变量**，同作用域可部分重声明（err 惯用法的地基）
- **复用 vs 遮蔽**：同一层大括号 = 复用；跨一层大括号 = 遮蔽（新变量）
- **`...` 的真相**：变参 ⇔ slice。声明侧 `...T` 收编、调用侧 `s...` 展开；append 靠它实现
- **make vs new**：make 只服务 slice/map/chan（零值 nil 不能直接用，需运行时搭内脏）；new 只给零值指针；`&T{...}` 一步构造是惯用法
- **可寻址性** = "有没有固定房间"：变量/slice元素/字段可寻址；map 元素（会搬家）、函数返回值（现炒）、字符串字节（共享只读）不可寻址 → 指针接收者方法要地址，值接收者只需复制
- **Go string ≈ `std::string_view`**：不拥有、只读、可共享；slice ≈ 私产可写数组
- **认得语法糖** = 读得懂编译器背后替我们写的那段代码
